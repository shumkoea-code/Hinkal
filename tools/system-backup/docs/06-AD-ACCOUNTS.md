# Бэкап доменных учётных записей (Active Directory)

Цель: **безопасно, быстро, с минимальной нагрузкой** на DC и сеть.

## Что выбирать

| Задача | Метод | Размер / нагрузка | Восстанавливает пароли? |
| --- | --- | --- | --- |
| Инвентарь пользователей/групп, атрибуты, членство | **Лёгкий CSV/LDIF экспорт** (`Backup-ADAccounts.ps1`) | КБ–МБ, LDAP page size | **Нет** |
| Поднять новый DC быстрее (реплика) | **IFM** (`ntdsutil` Install From Media) | Сотни МБ–ГБ, один раз локально | Да (для join DC) |
| Полный disaster recovery AD | **System State** (`Backup-SystemState.ps1` / wbadmin) | ГБ, VSS на DC | Да (весь каталог) |
| Образ всего DC | Disk / Hyper-V export | Очень тяжело | Да, но избыточно |

Для «просто учётки» чаще всего достаточно **лёгкого экспорта**. System State — отдельное ночное окно, не каждый час.

---

## 1. Лёгкий экспорт (рекомендуется ежедневно)

На DC или management-хосте с RSAT:

```powershell
cd tools\system-backup\windows
.\Backup-ADAccounts.ps1 -OutDir "E:\Backups\AD-light" -IncludeGroups -Keep 14
# опционально компьютеры + LDIF:
.\Backup-ADAccounts.ps1 -OutDir "E:\Backups\AD-light" -IncludeGroups -IncludeComputers -Ldif
```

Что внутри ZIP: `users.csv`, опционально `groups.csv` / `computers.csv`, `META.txt`, `.sha256`.

### Почему это «не грузит»

- Читает только нужные атрибуты (не весь объектный граф).
- `ResultPageSize` (по умолчанию 500) — пакетный LDAP, без гигантского ответа.
- Запускать **off-peak** (ночь / обед).
- Писать на **локальный диск**, потом доезжать на NAS **одним маленьким ZIP** (не live-rsync NTDS).
- Не трогает `NTDS.dit`, не держит долгий VSS.

### Безопасность

1. ZIP содержит PII (ФИО, mail, телефоны) — права NTFS только для backup-админов; шифровать BitLocker/на NAS.
2. **Парольные хеши не экспортируются** — это норма для лёгкого бэкапа.
3. Не класть экспорт в открытые шары и git.
4. Retention: `-Keep 14` (или по политике).

Восстановление атрибутов: правка вручную / скрипт `Set-ADUser` из CSV. Полный DC из CSV **не** поднимается.

## 2. IFM — быстро поднять новый DC

На здоровом DC (локальный диск, не через WAN):

```text
ntdsutil
  activate instance ntds
  ifm
    create sysvol full C:\IFM
    quit
  quit
```

Потом скопировать `C:\IFM` на новый сервер **в локальной сети** (или офлайн-носитель) и указать путь при `Install-ADDSDomainController -InstallationMediaPath ...`.

Нагрузка на WAN минимальна, если IFM везёте физически / ночным одним файлом после сжатия.

---

## 3. System State — полноценный бэкап AD

Ежедневно или после крупных изменений:

```powershell
.\Backup-SystemState.ps1 -BackupTarget "E:\Backups\AD"
```

Правила:

- Цель — **не** единственный системный диск DC (лучше отдельный том / NAS).
- Окно бэкапа — ночь; не параллелить с полным Hyper-V dump того же хоста.
- Периодически проверять restore на **изолированной lab-VM** (не в прод-домен!).
- Том с бэкапом исключить из антивируса на время окна, если режет VSS.

---

## 4. Чего избегать

| Плохая идея | Почему |
| --- | --- |
| `copy NTDS.dit` на горячую | Повреждение / несогласованность |
| Полный `dd`/образ DC по сети каждый день | Грузит диск, сеть, долгий RPO |
| Только CSV без System State «на всякий случай» | Не восстановите домен целиком |
| Бэкап только одного DC без SYSVOL/DNS | Неполный каталог |

---

## 5. Практичный минимум

1. **Каждую ночь:** `Backup-ADAccounts.ps1` → маленький ZIP на NAS.  
2. **Каждую ночь / через день:** System State на отдельный том.  
3. **Перед крупными изменениями схемы/ролей:** свежий System State + IFM.  
4. Раз в квартал: пробный restore System State в lab.

Связанные скрипты: `Backup-SystemState.ps1`, `Backup-Windows.ps1`, документация [02-WINDOWS.md](02-WINDOWS.md).
