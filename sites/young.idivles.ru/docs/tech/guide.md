# Техническая учётка (TECH)

## Назначение

Служебная роль для **включения/выключения любых публичных функций и разделов** сайта без деплоя, плюс режим техработ. Не предназначена для ежедневной контент-модерации.

- Панель: https://young.idivles.ru/ops  
- API: `GET/POST /api/ops/flags` (для не-TECH отвечает **404**)  
- Email учётки по умолчанию: `tech-ops@sochi.local` (задаётся `TECH_EMAIL` в `.env`)  
- Первый bootstrap: переменные `TECH_BOOTSTRAP_PASSWORD` / опционально `TECH_PASSWORD_HASH` (пароль **не** публикуется в этой документации)

## Как создаётся

При первом успешном входе на email из `TECH_EMAIL` с bootstrap-паролем (если пользователя ещё нет) создаётся запись `User` с ролью `TECH`. Далее вход — обычный bcrypt-пароль в БД.

## Куда ведёт интерфейс

| Действие | Результат |
|----------|-----------|
| Вход TECH | редирект на `/ops` |
| `/dashboard` | редирект на `/ops` |
| `/admin` | UI админки не для TECH (сервер/клиент уводят) |
| Публичные разделы | **всегда доступны TECH**, даже если модуль выключен |
| Режим maintenance | TECH обходит |

В шапке сайта кнопка «панели» для TECH ведёт на **Ops**.

## Панель Ops `/ops`

Возможности:

- Список модулей **группами** с поиском и фильтром «только выключенные».  
- Переключатель каждого модуля (Вкл/Выкл).  
- **Выключить всё публичное** (с подтверждением) / **Включить всё публичное**.  
- Текст техработ и ETA (для `/maintenance`); кнопка «Очистить ETA».  
- Счётчик выключенных, обновление списка.

### Модули (kill-switch)

| Ключ | Что режет |
|------|-----------|
| `registration` | `/register`, API регистрации |
| `messaging` | сообщения |
| `events` | афиша, билеты, check-in, API броней событий |
| `tickets_scan` | `/scanner` и API сканера |
| `places` | куда сходить |
| `gallery` | галерея |
| `projects` / `clubs` / `spaces` | каталоги |
| `programs` | гранты / добро / самоуправление |
| `vacancies` / `contests` | вакансии / конкурсы |
| `friends` / `games` / `news` / `portfolio` | соответствующие разделы |
| `maintenance` | зеркало `SiteSettings.maintenanceMode` (**false** в флаге = техработы **вкл**) |

Поведение для остальных ролей при выключении:

1. Edge Proxy → **307** на `/unavailable?m=<key>` (для страниц).  
2. API → **503** `MODULE_DISABLED`.  
3. Дополнительно страницы дергают `requireModulePage`.

Кэш флагов: Redis `yp:module-flags:v1` (~20 с) + память процесса; сброс при сохранении из Ops.

Экстренный обход всего kill-switch: env `MODULE_FLAGS_FORCE_ON=1` (не держать включённым в проде без нужды).

## Типовой сценарий

1. Войти как TECH → `/ops`.  
2. Выключить `events` → проверить инкогнито: `/events` → unavailable.  
3. Своей сессией TECH открыть `/events` — контент виден.  
4. Включить обратно или «Включить всё публичное».  
5. Не оставлять `maintenance` и массовое выключение без сообщения пользователям.

## Ограничения TECH

- Не заменяет админку контента.  
- `nav-counts` админки для TECH — 403 (норма).  
- Пароль bootstrap после первого входа лучше сменить через `/change-password` и ротацию `.env`.
