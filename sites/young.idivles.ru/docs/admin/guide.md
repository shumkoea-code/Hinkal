# Руководство администратора и модератора

Панель: https://young.idivles.ru/admin  
Вход: `/login` → после успеха редирект на `/admin` для ролей ADMIN и MODERATOR.

## Доступ

| Роль | Доступ |
|------|--------|
| **ADMIN** | Все разделы панели, пользователи, настройки, бэкап, РКН |
| **MODERATOR** | Только пункты, на которые выданы permissions (через «Пользователи» → смена роли/прав) |
| **TECH** | Админ-UI не использует; рабочая панель `/ops` |
| **USER / гость** | Нет |

Список прав модератора (ACL):  
`projects`, `clubs`, `spaces`, `places`, `bookings`, `applications`, `pages`, `programs`, `news`, `stats`, `scanner`, `portfolios`, `moderation`, `vacancies`, `contests`.

Только ADMIN: `/admin/users`, `/admin/settings`, `/admin/rkn`, `/admin/backup`.

В сайдбаре есть **поиск по разделам** и бейджи счётчиков (заявки, модерация, портфолио, афиша).

## Первый вход сотрудника (смена пароля)

**Реализовано:** при **назначении** роли `ADMIN`, `MODERATOR` или `SCANNER` пользователю выставляется флаг `mustChangePassword`.

При следующем входе Proxy перенаправляет на `/change-password` — пока пароль не сменён, остальной сайт недоступен (кроме auth-страниц).

На странице:

1. Ввести текущий (временный) пароль.  
2. Задать новый (≥ 8 символов) и подтвердить.  
3. После успеха — переход в `/admin` (или `/scanner` / кабинет по роли).  
4. Флаг сбрасывается; другие сессии инвалидируются.

Добровольная смена пароля также доступна в профиле `/dashboard` и на `/change-password`.

> Уже существующие сотрудники на момент внедрения флага **не** блокируются (`mustChangePassword = false`). Флаг включается при **смене роли** на staff.

## Дашборд `/admin`

- Сводные счётчики: заявки, пользователи (ADMIN), проекты/клубы/пространства.  
- **Аналитика** — период (день/неделя/месяц/…), график регистраций, круговая статусов заявок, проходы QR.  
- Блоки «ожидают» / сегодняшние события / модерация (по правам).  
- Ссылка «Проходы QR» → `/admin/stats`.

## Разделы панели (по смыслу)

### Контент
- **Проекты / Клубы / Пространства / Куда сходить** — карточки каталога, публикация, правки.  
- **Гранты и добро** — программы (`/grants`, `/dobro`, `/self-gov`).  
- **Страницы** — CMS `/p/[slug]`.  
- **Команда «О нас»**, **Документы**, **Новости**.

### Операции
- **Афиша** (`/admin/bookings`) — модерация событий/броней, статусы PENDING → APPROVED/…  
- **Заявки** — в клубы/проекты/программы.  
- **Портфолио** — модерация работ пользователей.  
- **Вакансии / Конкурсы**.  
- **Модерация** — жалобы на контент/переписки (в т.ч. связка с Telegram при настройке).  
- **Статистика** — проходы и периоды.  
- **Сканер** — веб-сканер QR (камера).

### Система (ADMIN)
- **Пользователи** — поиск, фильтр по ролям, карточка пользователя, смена роли и permissions, блок/разблок, карма/рейтинги. TECH в списке скрыт.  
- **РКН / ПДн** — регуляторные процедуры.  
- **Бэкап** — выгрузки (осторожно с секретами).  
- **Настройки** — имя сайта, доступы, галерея, видимость событий, техработы (частично дублируется TECH `/ops`).

## Типовые сценарии

### Одобрить событие
1. `/admin/bookings` → PENDING.  
2. Проверить площадку, время, организатора.  
3. Одобрить → появится в `/events`.

### Назначить модератора
1. `/admin/users` → найти пользователя.  
2. Роль `MODERATOR` + отметить нужные permissions.  
3. Сообщить временный пароль (если создавали/сбрасывали вне системы).  
4. При **смене роли** на MODERATOR/ADMIN/SCANNER включится обязательная смена пароля при входе.

### Модерация портфолио
1. `/admin/portfolios` → на проверке.  
2. Одобрить / отклонить.  
3. Одобренные доступны к просмотру/скачиванию на публичном профиле.

## Безопасность для админов

- Не передавайте пароли TECH и `.env`.  
- После работы на чужом ПК — «завершить другие сессии» в кабинете.  
- Массовые выключения разделов — зона TECH (`/ops`), не путать с CMS.  
- Бэкапы и выгрузки ПДн — только по процедуре РКН.

## Связь с TECH

Если «пропал» целый раздел у всех пользователей — скорее выключен модуль в `/ops`.  
Админ **не** управляет kill-switch; пишет технической службе.
