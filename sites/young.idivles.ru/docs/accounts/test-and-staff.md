## 2. Первый вход администратора / сотрудника — смена пароля

### Как реализовано

1. Админ в `/admin/users` меняет роль пользователя на `ADMIN`, `MODERATOR` или `SCANNER`.  
2. В БД выставляется `User.mustChangePassword = true`.  
3. При входе JWT содержит флаг; **Proxy** перенаправляет на `/change-password`.  
4. Пользователь задаёт новый пароль через `POST /api/auth/change-password`.  
5. Флаг сбрасывается в `false`, `tokenVersion` увеличивается (другие сессии гаснут).  
6. Редирект: ADMIN/MOD → `/admin`, SCANNER → логика сканера, иначе кабинет.

Добровольно пароль меняется в профиле `/dashboard` (поля текущего/нового пароля) — тоже снимает флаг.

Страница: `/change-password`.

### Рекомендуемая процедура онбординга админа

1. Создать/найти пользователя с рабочим email.  
2. Выдать роль ADMIN (включится mustChangePassword).  
3. Передать **временный** пароль по защищённому каналу.  
4. Сотрудник входит → обязан сменить пароль → работает в `/admin`.  
5. Включить 2-й фактор процессный: доверенные устройства в кабинете «Безопасность».

## 9. Сброс пароля тестовых учёток (для админа стенда)

На сервере (пример):

```bash
cd /opt/sochi-portal
HASH=$(docker-compose exec -T web node -e 'require("bcrypt").hash("NEW_PASSWORD",10).then(h=>process.stdout.write(h))')
docker-compose exec -T db psql -U sochi -d sochi_portal -c \
  "UPDATE \"User\" SET password='$HASH', \"mustChangePassword\"=true WHERE email='qa-admin@sochi.ru';"
```

После входа QA-админ будет обязан сменить пароль на `/change-password`, если флаг `true`.
