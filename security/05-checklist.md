# 05. Чек‑лист для углублённого (авторизованного) тестирования

Этот список выполняется **только владельцем сайта или с его письменного разрешения**,
желательно на тестовом стенде (копии сайта), а не на боевом сервере.

## Транспорт и заголовки (можно проверить пассивно)

- [ ] HSTS присутствует и с адекватным `max-age`.
- [ ] CSP включён (сначала Report‑Only), нет `unsafe-inline`/`unsafe-eval` в `script-src`.
- [ ] Есть `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- [ ] Защита от кликджекинга (`frame-ancestors`/`X-Frame-Options`).
- [ ] `server_tokens off`, версия ПО не раскрывается.
- [ ] Оценка TLS на [SSL Labs](https://www.ssllabs.com/ssltest/) не ниже A
      (протоколы TLS 1.2/1.3, отключены устаревшие).
- [ ] Неизвестные пути дают `404`, каталоги не листаются.

## Фронтенд (SPA)

- [ ] В бандле нет секретов/ключей (API‑ключи, токены, пароли).
- [ ] Нет использования `dangerouslySetInnerHTML` без санитизации.
- [ ] Зависимости без известных уязвимостей (`npm audit`, обновление пакетов).
- [ ] Sourcemaps не выкладываются в прод (или выкладываются осознанно).

## Backend / API онлайн‑заказа

- [ ] Вся серверная валидация ввода (не полагаться на клиентскую).
- [ ] Защита от инъекций: параметризованные запросы к БД, экранирование вывода.
- [ ] Защита от CSRF на изменяющих запросах.
- [ ] Rate limiting и анти‑спам на форме заказа.
- [ ] Авторизация/доступ к админке и служебным эндпоинтам.
- [ ] Нет IDOR (доступ к чужим заказам по перебору id).
- [ ] Корректная обработка ошибок без утечки стека/SQL в ответе.
- [ ] Логирование и мониторинг подозрительной активности.

## Персональные данные (152‑ФЗ)

- [ ] Согласие на обработку ПДн на форме заказа.
- [ ] Политика конфиденциальности опубликована.
- [ ] ПДн передаются и хранятся только по HTTPS/шифрованно.
- [ ] Минимизация: собираются только нужные для заказа данные.

## Инфраструктура

- [ ] Регулярные обновления ОС и nginx (`unattended-upgrades`).
- [ ] Файрвол: открыты только 80/443 (и нужные служебные порты по allowlist).
- [ ] Резервные копии и план восстановления.
- [ ] Автопродление TLS‑сертификата (`certbot renew`).
- [ ] Разделение прав: приложение не работает под root.

## Инструменты для авторизованного теста (на стенде)

- OWASP ZAP / Burp Suite — анализ HTTP‑трафика и активные проверки.
- `nikto`, `testssl.sh` — конфигурация веб‑сервера и TLS.
- `npm audit` / `osv-scanner` — уязвимости зависимостей.
- Ориентир по классам уязвимостей — [OWASP Top 10](https://owasp.org/www-project-top-ten/).
