## Подробности

### F‑1. Отсутствует HSTS
**Наблюдение.** В ответе главной страницы (и ассетов) нет заголовка `Strict-Transport-Security`.

Заголовки ответа `curl -I https://hinkalnayaureki.ru/`:
```
HTTP/2 200
server: nginx/1.18.0 (Ubuntu)
content-type: text/html
content-length: 1124
last-modified: Mon, 03 Aug 2026 23:09:58 GMT
etag: "6a711fc6-464"
accept-ranges: bytes
```
**Риск.** Без HSTS первый заход по `http://` или подмена в сети (MITM, SSL‑stripping) может
увести пользователя на незащищённое соединение до срабатывания редиректа.
**Исправление:** [R‑1](04-remediation.md#r-1-hsts).

### F‑2. Отсутствует Content-Security-Policy
**Наблюдение.** Заголовка `Content-Security-Policy` нет. Страница подгружает сторонние ресурсы
(Google Fonts: `fonts.googleapis.com`, `fonts.gstatic.com`).
**Риск.** CSP — ключевая защита от XSS и внедрения стороннего кода. Для сайта с онлайн‑заказом
(вводятся имя, телефон, адрес) это важный слой защиты от кражи данных через инъекции скриптов.
**Исправление:** [R‑2](04-remediation.md#r-2-csp).

### F‑3. Отсутствует X-Content-Type-Options
**Наблюдение.** Нет `X-Content-Type-Options: nosniff`.
**Риск.** Браузер может «угадывать» MIME‑тип и исполнить файл не так, как задумано
(MIME‑sniffing), что расширяет поверхность для XSS.
**Исправление:** [R‑3](04-remediation.md#r-3-прочие-заголовки).

### F‑4. Нет защиты от кликджекинга
**Наблюдение.** Нет ни `X-Frame-Options`, ни директивы `frame-ancestors` в CSP.
**Риск.** Сайт можно встроить в `<iframe>` на чужой странице и обманом заставить пользователя
кликать по невидимым элементам (clickjacking).
**Исправление:** [R‑3](04-remediation.md#r-3-прочие-заголовки).

### F‑5. Нет Referrer-Policy и Permissions-Policy
**Наблюдение.** Оба заголовка отсутствуют.
**Риск.** Без `Referrer-Policy` во внешние домены (шрифты, аналитика) может утекать полный URL.
Без `Permissions-Policy` не ограничен доступ к камере/микрофону/геолокации для встроенного кода.
**Исправление:** [R‑3](04-remediation.md#r-3-прочие-заголовки).

### F‑6. Раскрытие версии ПО
**Наблюдение.** Заголовок `Server: nginx/1.18.0 (Ubuntu)` присутствует во всех ответах,
включая редирект с порта 80.
**Риск.** Точная версия сервера и дистрибутива упрощают злоумышленнику подбор известных
эксплойтов. Это раскрытие информации (information disclosure).
**Исправление:** [R‑4](04-remediation.md#r-4-скрыть-версию-сервера).

### F‑7. Устаревшая версия nginx
**Наблюдение.** `nginx/1.18.0` — стабильная ветка из Ubuntu 20.04, давно не самая свежая.
**Риск.** Отсутствие свежих патчей безопасности. Требуется обновление и регулярное
применение обновлений ОС/пакетов.
**Исправление:** [R‑5](04-remediation.md#r-5-обновление-и-патчи).

### F‑8. SPA‑fallback отдаёт 200 на любые пути
**Наблюдение.** Запросы `/.well-known/security.txt`, `/sitemap.xml`, `/assets/` возвращают
`HTTP 200` с телом главной страницы `index.html` (это классический SPA‑fallback
`try_files $uri /index.html`), а не `404`.
**Риск.** Низкий, но: несуществующие ресурсы отдают `200 text/html`, что мешает мониторингу,
SEO и корректной обработке ошибок клиентом. Директория не листается — это хорошо;
проблема именно в коде ответа для неизвестных путей.
**Исправление:** [R‑6](04-remediation.md#r-6-корректный-404-и-fallback).

### F‑9. Нет реального security.txt
**Наблюдение.** `/.well-known/security.txt` не существует (отдаётся SPA‑fallback).
**Риск.** Информационная: нет стандартного канала для сообщений об уязвимостях
([RFC 9116](https://www.rfc-editor.org/rfc/rfc9116)).
**Исправление:** [R‑7](04-remediation.md#r-7-securitytxt).

### F‑10. Backend онлайн‑заказа (не проверялся)
**Наблюдение.** На главной заявлен онлайн‑заказ. Форма/адрес API обрабатывают ПДн
(имя, телефон, адрес доставки), возможно — платежи.
**Статус.** Намеренно **не** тестировался: это выходит за рамки пассивного аудита и требует
разрешения владельца. Это самая значимая по риску часть системы.
**Что делать:** пройти чек‑лист [`05-checklist.md`](05-checklist.md) на своём стенде.
