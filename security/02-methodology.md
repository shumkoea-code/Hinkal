# 02. Методология, границы и правила проверки

## Подход

Аудит выполнен по принципу **«пассивной чёрной коробки» (passive black‑box)**: анализируются
только те данные, которые сервер добровольно отдаёт любому браузеру при обычном просмотре
страницы. Это исключает риск нарушить работу сайта или закон.

## Границы (scope)

**В границах (разрешено, неинвазивно):**

- `GET`/`HEAD`‑запросы главной страницы и её публичных ресурсов (JS/CSS/иконки).
- Чтение HTTP‑заголовков ответа.
- Просмотр TLS‑сертификата (данные, которые сервер сам предъявляет при рукопожатии).
- Обращение к стандартным публичным файлам: `robots.txt`, `sitemap.xml`,
  `/.well-known/security.txt`.
- Проверка поведения редиректа `http → https`.
- Проверка реакции на обращение к несуществующему пути (какой код ответа возвращается).

**Вне границ (запрещено без письменного разрешения):**

- Сканирование портов и сервисов (nmap и т.п.).
- Тесты на уязвимости приложения: SQLi, XSS, CSRF‑эксплуатация, SSRF, path traversal,
  загрузка файлов, обход авторизации.
- Брутфорс, перебор директорий/поддоменов (dirbusting), фаззинг параметров.
- Нагрузочное и DoS‑тестирование.
- Любые запросы, изменяющие данные (создание заказов, отправка форм с реальными данными).

## Инструменты (только для пассивного сбора)

- `curl` — просмотр заголовков и тела ответа.
- `openssl s_client` — просмотр TLS‑сертификата.
- Ручной анализ HTML/JS, отдаваемого сайтом.

## Что было выполнено фактически

1. Запрос заголовков главной страницы (`curl -I`).
2. Загрузка HTML главной страницы и определение стека (Vite + React SPA).
3. Просмотр TLS‑сертификата (издатель, срок действия, subject).
4. Проверка редиректа с `http://` на `https://`.
5. Запрос `robots.txt`, `sitemap.xml`, `/.well-known/security.txt`.
6. Проверка кода ответа для несуществующих путей (поведение SPA‑fallback).
7. Проверка заголовков на статических ассетах (`/assets/*.js`).

## Оговорка (disclaimer)

Аудит охватывает только видимую снаружи поверхность и **не** заменяет полноценный
penetration test с ведома владельца. Наиболее рискованная часть — backend онлайн‑заказа
(обработка ПДн: имя, телефон, адрес) — намеренно **не** тестировалась и вынесена в
чек‑лист для авторизованной проверки ([`05-checklist.md`](05-checklist.md)).
