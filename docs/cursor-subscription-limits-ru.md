## 1. Сколько у меня осталось до лимита — где посмотреть

Персональные данные о расходах и остатке лимита есть только в вашем аккаунте Cursor. Ни у агента, ни у кого-то со стороны доступа к ним нет, поэтому цифру остатка нужно посмотреть самостоятельно — она есть в четырёх местах:

| Где | Ссылка | Что показывает |
| --- | --- | --- |
| **Вкладка Spending** (главное место) | [cursor.com/dashboard/spending](https://cursor.com/dashboard/spending) | Расход по обоим пулам в реальном времени, **остаток включённого лимита**, начисления on-demand, **дату сброса лимита**, стоимость отдельных запросов; здесь же настраиваются лимиты траты и оповещения |
| **Usage dashboard** | [cursor.com/dashboard/usage](https://cursor.com/dashboard/usage) | Включённое использование отдельно по пулам Cursor Models и Other Models |
| **Billing & Invoices** | [cursor.com/dashboard](https://cursor.com/dashboard) → Billing & Invoices | Два раздела: Included Usage (покрыто подпиской) и On-Demand Usage (сверх подписки), счета |
| **Настройки редактора** | Cursor → Settings | Оба пула видны прямо в редакторе, без открытия браузера |

Что важно понимать про «остаток»:

- Лимит сбрасывается **раз в месяц по дате оформления подписки**, а не первого числа календарного месяца. Точная дата сброса написана на вкладке Spending.
- **Неиспользованный остаток не переносится** на следующий месяц.
- У вас **два независимых лимита** (см. следующий раздел), и они расходуются отдельно. Может закончиться один, а второй ещё останется.
- Если вы участник командного тарифа (Teams), вы видите свой персональный остаток; лимит выделяется каждому участнику по типу места и **между участниками не переносится**.

Судя по тому, что у вас работают Cloud Agents (фоновые агенты в облаке), у вас **платный тариф** — облачные агенты недоступны на бесплатном Hobby. Какой именно из платных, видно на странице [cursor.com/dashboard/billing](https://cursor.com/dashboard/billing).

## 2. Как устроена тарификация в 2026 году

Главное изменение по сравнению с 2024–2025 годами: **счёт идёт не в «запросах», а в токенах и деньгах**. Старая модель с «premium requests» и «быстрыми/медленными запросами» официально названа legacy (устаревшей). Пользователей старых тарифов переводят на новую схему при очередном продлении подписки.

### Два пула использования

У каждого тарифа есть **два отдельных месячных пула**, каждый сбрасывается вместе с биллинговым циклом:

**1. Cursor Models** («пул первых моделей»)

- Модели: **Cursor Grok 4.5** и **Composer 2.5** (собственные модели Cursor).
- Включённого лимита здесь «значительно больше» — в документации формулировка «generous included usage». Точная сумма в долларах **не документирована ни для одного тарифа**.
- Освобождён от надбавки Cursor Token Rate.

**2. Other Models** («пул сторонних моделей»)

- Все сторонние модели: Anthropic Claude, OpenAI GPT, Google Gemini, Moonshot Kimi, Z.ai GLM.
- Тарифицируется **по API-цене модели без наценки** («no markup»).
- Тарифы Pro, Pro Plus и Ultra включают минимум $20 такого использования в месяц (больше на старших тарифах).

Практический вывод: выбор модели напрямую определяет, как быстро тают деньги. Composer 2.5 ($0,5 за миллион входных токенов) и Claude Fable 5 ($10 за миллион входных и $50 за миллион выходных) отличаются по стоимости в десятки раз.

### Из чего складывается счёт

Согласно Pricing Policy (§2.4, §9), **Total Tokens** — это суммарное количество токенов по всем операциям: вход, выход и кэш (и чтение, и запись). Стоимость = Total Tokens × тариф модели. То есть кэш тоже считается, просто по своим (обычно сильно меньшим) ставкам.

Дополнительные множители, которые могут увеличить счёт:

- **Cursor Token Rate** — $0,25 за миллион токенов, только на Teams и Enterprise (подробнее в разделе 10).
- **Региональное размещение данных** (data residency) — надбавка **+10 %** к цене моделей для подходящих моделей.
- **Fast-режимы моделей** — как правило ×2 к цене (у Claude Opus 4.7 fast — в разы дороже).
- **Long context** — у части моделей (GPT-5.4, GPT-5.5, GPT-5.6 Sol) контекст до 1M токенов стоит ×2 по входным токенам; у моделей Claude 4.5–5 и Kimi K3 надбавки за длинный контекст нет.

Важные оговорки по ценам:

- **Все цены указаны без налогов.** Единственное исключение — индийский тариф Start, где цена с налогом.
- **Годовые цены в долларах официально не публикуются.** Единственная документированная цифра: для Teams «экономия 20 % при переходе с месячной на годовую оплату». На странице цен есть переключатель Monthly/Yearly, но сами суммы в документации отсутствуют.
- **Минимального количества мест для Teams нет.** Ограничения такие: в команде всегда должен быть хотя бы один админ и хотя бы один платный участник; бесплатный Unpaid Admin требует наличия хотя бы одного платного пользователя; один аккаунт не может состоять более чем в одной команде.
- Тип места (Standard/Premium) не связан с ролью (Member/Admin) — их назначают независимо. Переход Standard → Premium действует сразу с пересчётом на остаток цикла; Premium → Standard — только с конца цикла.
- **Подписки продаются только напрямую на cursor.com.** Официально: «Мы не авторизуем никаких реселлеров и сторонних продавцов», аккаунты из других источников могут быть заблокированы.
- **Покупка через App Store (iOS):** доступны только месячные Pro, Pro+ и Ultra; годовых, Teams и Enterprise там нет. У таких подписчиков **нельзя включить on-demand** (Cursor не хранит их платёжный метод), а возврат делает только Apple.

## 4. Что входит в каждый тариф

**Hobby (бесплатно)**

- Агент, чат и Tab-автодополнение на модели Auto.
- «Ограниченное число запросов к агенту», доступ к Composer.
- Доступен меньший набор моделей, чем на платных тарифах.
- Карта при регистрации не требуется.
- Точные числовые лимиты Hobby **не документированы**.

**Pro / Pro Plus / Ultra**

- **Неограниченное Tab-автодополнение.**
- Расширенные лимиты агента на **всех** моделях, доступ к frontier-моделям.
- **Cloud Agents** (облачные агенты) и **Bugbot** (ревью кода).
- MCP-серверы, плагины, hooks, skills, Cursor SDK, Automations.
- Возможность выбирать уровень reasoning-усилий и включать Fast-режимы.
- Различаются только объёмом включённого лимита: $20 / $70 / $400 в пуле Other Models.

**Start (только Индия, ₹649/мес)**

- Включено: агент, режимы Plan и Ask, Cloud Agents, Cursor для iOS, плагины, MCP-серверы, hooks, skills. Модели — только Grok 4.5 и Composer 2.5.
- Ограничения: обе модели работают в non-fast режиме, Grok 4.5 зафиксирован на среднем (medium) уровне усилий, менять это нельзя.
- **Не включено:** пул Other Models, on-demand, Bugbot, Auto, Automations, Cursor SDK.
- Grok 4.5 расходует пул примерно **в 3 раза быстрее**, чем Composer 2.5.
- При исчерпании лимита ИИ-функции **приостанавливаются до следующего цикла** — доплатить нельзя.

**Teams** — всё из Pro плюс: централизованный биллинг и администрирование, командный маркетплейс внутренних правил/скиллов/плагинов, агентное ревью кода Bugbot, облачные агенты и автоматизации с общим командным контекстом, аналитика использования, принудительный Privacy Mode на всю команду, SAML/OIDC SSO, Cursor Router.

**Enterprise** — всё из Teams плюс: pooled usage (общий пул на всю организацию), оплата по счёту/PO, SCIM-провижининг мест, ограничения доступа к репозиториям/моделям/MCP, контроль auto-run, браузера и сети, audit logs, сервисные аккаунты, AI Code Tracking API, приоритетная поддержка и аккаунт-менеджмент.

## 5. Что происходит при достижении лимита

1. **В редакторе появляется уведомление** о том, что включённое использование закончилось.
2. Дальше два пути: **включить on-demand** (оплата по факту) или **перейти на старший тариф**.
3. **Качество и скорость запросов при этом не понижаются** — официальная формулировка: «Requests are never downgraded in quality or speed». Никакой «медленной очереди», как в старых тарифах, нет.
4. Если on-demand **выключен**, запросы просто перестают выполняться до сброса лимита.

**Особая логика для Teams:** когда участник израсходовал весь включённый лимит сторонних моделей, Cursor **автоматически переключает его на пул Cursor Models**. Если он продолжает пользоваться сторонними моделями или исчерпал и второй пул — он переходит на on-demand, если тот включён.

**Особая логика для Start:** on-demand отсутствует, функции приостанавливаются до сброса лимита.

## 6. On-demand: оплата сверх лимита

- Позволяет продолжать работу после исчерпания включённого лимита **по тем же API-ценам**, по факту потребления.
- **Выставляется постфактум, раз в месяц**, отдельными позициями в счёте (не смешивается с подпиской).
- Для индивидуальных тарифов **нужно включить вручную**: [cursor.com/dashboard/spending#on-demand-usage](https://cursor.com/dashboard/spending#on-demand-usage).
- Для **Teams включён по умолчанию**.
- **Недоступен** на тарифе Start и для подписок, купленных через App Store.

### Все способы получить больше лимита

1. **Переключиться на модели Cursor** (Grok 4.5, Composer 2.5) — это отдельный пул, который, скорее всего, ещё не исчерпан.
2. **Включить on-demand.**
3. **Перейти на старший тариф** — Pro+ ($60/мес, включено $70) или Ultra ($200/мес, включено $400).
4. **BYOK** — подключить свои API-ключи в Cursor Settings → Models. Внимание: на Teams и Enterprise **Cursor Token Rate ($0,25/млн токенов) взимается и при BYOK**, вдобавок к тому, что вы платите своему API-провайдеру напрямую.
5. **Enterprise pooled usage** — неиспользованные объёмы перераспределяются на тех, кому они нужны.

## 7. Лимиты траты и уведомления

### Spend limits (жёсткий предел расходов)

- Настраиваются на [cursor.com/dashboard/spending](https://cursor.com/dashboard/spending). **Чтобы увидеть и задать лимит, должен быть включён on-demand.** Изменения применяются немедленно; значение «No Limit» снимает ограничение.
- **При достижении лимита:** ИИ-функции отключаются у конкретного пользователя, остальные участники команды не затрагиваются, пользователь видит уведомление, работа автоматически возобновляется в начале следующего биллингового цикла.
- **Индивидуальные тарифы** (Pro, Pro+, Ultra): месячный лимит на собственный on-demand.
- **Teams:** лимит на всю команду; при достижении ИИ-функции отключаются у всех, кто расходует on-demand.
- **Enterprise:** лимиты и на команду, и на отдельных участников — через переопределения на вкладке Members, групповые переопределения на вкладке Groups или общий командный лимит на вкладке Spending. Если лимиты приходят из нескольких источников, **применяется наибольший из применимых**. Доступно и через Admin API.
- Изменение командного лимита **не обновляет уже существующие персональные и групповые переопределения** — их нужно снимать вручную.
- **Dynamic Spend Limits** — автоматическая подстройка командного лимита под размер команды, пропорционально числу мест. Включается на вкладке Spending.
- На Enterprise с pooled usage персональные лимиты применяются к **общему** расходу, а не только к on-demand.
- Согласно Pricing Policy §7.2, администраторы аккаунта вправе устанавливать **жёсткие предельные лимиты (hard caps)** на использование в организации.

### Spend alerts (предупреждения по email)

- Письмо приходит, когда расход on-demand достигает заданного вами порога. **Оповещения не останавливают работу** — для остановки нужны spend limits.
- Настройка: [cursor.com/dashboard/spending](https://cursor.com/dashboard/spending) → **Add Alert** → выбрать уровень (команда или участник) → задать порог.
- Порог считается **только по on-demand**; включённое использование в него не входит. Исключение — Enterprise с pooled usage, где можно настроить оповещения по общему расходу.
- Админ решает, кому отправлять персональные оповещения: администраторам, самому участнику или обоим.
- Это **единственный документированный механизм предупреждения** о приближении к лимиту. Предупреждений в процентах от включённого лимита (вроде «вы израсходовали 80 %») в документации нет.

## 8. Auto и Cursor Router

Режим Auto теперь работает на **Cursor Router** и имеет **три режима**:

| Режим | Логика | Тарификация |
| --- | --- | --- |
| **Auto Cost** | Прежняя логика Auto; сохраняет функциональность и цены старого режима Auto. Пользователей прежнего Auto перевели именно сюда | Фиксированная ставка независимо от выбранной моделью: **$1,25/млн вход**, $1,25/млн запись кэша, **$0,25/млн чтение кэша**, **$6,00/млн выход**. Освобождён от Cursor Token Rate |
| **Auto Balance** | Баланс интеллекта, скорости и стоимости | По API-цене фактически использованной модели + Cursor Token Rate для сторонних моделей |
| **Auto Intelligence** | Направляет на самые сильные модели для сложных задач | Так же, как Balance |

**Важно про деньги:** Balance и Intelligence в среднем стоят **примерно в 2 раза дороже** Cost, а в зависимости от режима — **до 2–4 раз дороже**. У Cursor есть отдельный пункт в FAQ «Почему выросли мои расходы после запуска Cursor Router» именно с этим объяснением. Если счёт неожиданно вырос — проверьте, не переключён ли Auto в Balance или Intelligence.

**Auto нигде не является безлимитным или бесплатным.** У Auto Cost есть явные ставки за токены, и он расходует пулы. Запросы через Router могут расходовать оба пула — в зависимости от того, какая модель обработала запрос.

**Доступность:** Cursor Router пока доступен **только на Teams и Enterprise**. Индивидуальные тарифы (Hobby, Pro, Pro+, Ultra) получат его позже — формулировка документации: «через несколько месяцев после запуска». На Enterprise Router по умолчанию выключен, включает администратор.

**Модели, между которыми маршрутизирует Router:** GPT-5.5, Claude Opus 5, Grok 4.5, Claude Fable 5. **Grok 4.5 обязателен** — если его заблокировать, Router отключается. GPT-5.5 и Claude Opus 5 рекомендованы: блокировка одной ухудшает качество маршрутизации, блокировка обеих отключает Router.

**Админ-настройки:** включение/отключение Router; выбор доступных участникам режимов (можно отключить до двух); видимость выбранной модели (Hidden по умолчанию или Displayed); «Impose Auto» — **Soft** (новый чат по умолчанию на Auto, можно переключить) или **Hard** (выбор модели заблокирован на Auto). Обе опции выключены по умолчанию.

В Cursor SDK: идентификатор модели `auto-smart`, параметр `optimize_for` со значениями `cost`, `balanced`, `intelligence`.

## 11. Отдельно оплачиваемые возможности

### Cloud Agents (облачные агенты, ранее Background Agents)

- Тарифицируются **по API-цене выбранной модели**. Отдельной платы за виртуальную машину или машинное время **в документации нет**.
- Можно выбрать размер контекстного окна, и **больший контекст увеличивает расход токенов и стоимость**.
- **При первом использовании вас попросят задать лимит траты (spend limit).**
- Доступны на **всех платных тарифах**, включая Start. На бесплатном Hobby — недоступны.
- Запускать можно **сколько угодно агентов параллельно**; числового ограничения в документации нет.
- Панель управления: [cursor.com/dashboard/cloud-agents](https://cursor.com/dashboard/cloud-agents) — статусы, логи, потребление ресурсов, окружения, секреты, настройки.
- Автоисправление упавшего CI на PR облачного агента доступно **на тарифах Teams**; отключается на конкретном PR командой `@cursor autofix off`.
- Админы команды могут включать/отключать «Long running agents», а на Enterprise — «Computer use».

### Bugbot (агентное ревью кода)

- Перешёл на **тарификацию по использованию**, а не по местам.
- **Средний прогон Bugbot стоит от $1,00 до $1,50** в зависимости от размера и сложности PR.
- **Индивидуальные тарифы:** списывается сначала из включённого лимита, затем из on-demand. Если on-demand выключен, Bugbot приостанавливается до следующего цикла.
- **Teams:** ревью списываются **из on-demand**, а не из включённого лимита.
- **Уровни усилий** (только на usage-based тарифах): **Default**, **High** (дороже, дольше, находит больше проблем), **Custom** (описание на естественном языке, когда какой уровень применять).
- **Bugbot Autofix** запускает облачного агента и тарифицируется по ставкам вашего тарифа. Требует включённого on-demand и включённого хранения данных (не работает при Legacy Privacy Mode). Максимум **3 попытки на PR** при коммите в существующую ветку.
- MCP-поддержка Bugbot — только на Teams и Enterprise.
- Лимиты правил: одно правило обрезается на **30 000 символов**, суммарно правила — не более **100 000 символов** на ревью.
- Лимиты API: `POST /bugbot/review` — **30 запросов в минуту на команду** (dry-run дополнительно ограничен 10 в минуту); Admin Configuration API — **60 запросов в минуту на команду**.
- **Переход на новую тарификацию:** новые клиенты — сразу; существующие — при первом продлении **после 8 июня 2026 года**. Пример из документации: цикл, начавшийся 1 мая 2026, переходит с цикла 1 июля (не 1 июня). Годовая подписка, купленная в мае 2026, — при продлении в мае 2027. Досрочно переключиться можно на [cursor.com/dashboard/bugbot?modal=migrate-bugbot](https://cursor.com/dashboard/bugbot?modal=migrate-bugbot) с пропорциональным возвратом уже оплаченных за места сумм в виде кредитов.
- **Старая (legacy) схема Bugbot:** для частных лиц $40/мес за до 200 PR в месяц по всем репозиториям; для команд $40 за пользователя в месяц, где «пользователь» — тот, чьи PR были отревьюены в этом месяце; общий предохранитель — 200 PR в месяц на лицензию (например, 100 пользователей → 20 000 PR/мес), по запросу увеличивается.

### Max Mode

- **Max Mode доступен только на устаревших (legacy) request-based тарифах.** На текущих usage-based тарифах его нет.
- На legacy-тарифах он расширяет контекстное окно модели сверх стандартного и тарифицируется **по API-цене модели +20 %**. Там же он давал субагентов, генерацию изображений и доступ к новейшим frontier-моделям.
- Многие модели помечены «Requires Max Mode on legacy request-based plans»: все Claude Opus/Sonnet 4.5 и новее, Fable 5, GPT-5.3 Codex, GPT-5.4, GPT-5.5, GPT-5.6 Sol, Kimi K3.
- На современных тарифах длинный контекст решается ценой моделей: у части моделей ×2 по входу за 1M-контекст, у части — без надбавки.

### Вызовы инструментов и кэш

- **Ограничения на количество вызовов инструментов нет:** «There is no limit on the number of tool calls Agent can make during a task». Отдельной платы за вызов инструмента нет — они тарифицируются через токены.
- Кэш тарифицируется отдельными колонками: чтение кэша обычно составляет 10 % от цены входа (например, Claude Sonnet: $3 вход против $0,30 чтение кэша), запись кэша обычно ×1,25 от входа.

### Conversation Insights (Enterprise)

Классифицирует работу по категории, типу, сложности и специфичности; работает на устройстве; включено по умолчанию. **Было бесплатно в период превью; с 1 января 2026 года инференс тарифицируется.**

Панель [cursor.com/dashboard/analytics](https://cursor.com/dashboard/analytics) показывает: долю ИИ в закоммиченном коде, правки агента, Tab-автодополнения (количество подсказок, не строк), отправленные сообщения (с фильтром по режиму и модели), активных пользователей, ежедневное использование за 365 дней, лидерборд (чаты / принятые Tab-подсказки / строки кода от агента, плюс любимая модель), инсайты по репозиториям, использование облачных агентов (создано агентов, открыто и смёржено PR, строк кода), топ репозиториев и пользователей по облачным агентам, версии клиента.

Ограничения: фильтрация — до **10 пользователей** и **90 непрерывных дней**. Выгрузка CSV по отдельному графику или по всем сразу. Данные собираются только с **версии клиента 1.5 и выше**. Analytics API — только Enterprise.

## 15. Оплата, смена тарифа, отмена и возвраты

### Биллинговый цикл

Начинается с даты оформления подписки. Индивидуальные тарифы продлеваются по дате регистрации, Teams — по дате регистрации команды. **Даты продления не меняются при добавлении или удалении участников.**

### Смена тарифа

- **Апгрейд действует немедленно.**
- **Даунгрейд** — это «Schedule Downgrade»: текущий тариф сохраняется до конца оплаченного периода.
- Переход с месячной на годовую оплату — через зелёный баннер «Upgrade Now».
- **С годовой на месячную посреди периода перейти нельзя**: только запланировать на конец года; для Teams — «отменить, дождаться конца года, подписаться заново».

### Отмена

Через [cursor.com/dashboard/billing](https://cursor.com/dashboard/billing) → Manage Subscription (Stripe-портал) → Cancel Subscription. Платные функции сохраняются до конца оплаченного периода, затем аккаунт возвращается на бесплатный **Hobby**. Отмена не удаляет аккаунт и локальные файлы.

Кнопка отмены скрыта, если: тариф уже истёк, есть неоплаченный счёт, вы участник команды без прав админа, либо подписка оформлена через iOS.

### Возвраты

Для Pro, Pro+ и Ultra правила одинаковы для месячной и годовой оплаты. Возврат **последнего платежа** возможен, если **одновременно**:

1. платёж был сделан **в течение последних 14 дней**, и
2. **вы не пользовались подпиской** в этом расчётном периоде.

Деньги возвращаются на исходный способ оплаты в течение **5–10 рабочих дней**. Вне 14-дневного окна или при наличии использования платёж, как правило, не возвращается, и вы считаетесь обязанным по текущему периоду. **Начисления за on-demand и fast-requests за уже потреблённое не возвращаются.** Для покупок через iOS возврат делает только Apple. Cursor просит связаться с поддержкой до оспаривания платежа в банке. Политика не ограничивает прав потребителя по применимому законодательству. Для Teams публично описана только возможность корректировки биллинга в виде кредита на будущий счёт.

### Студенческая скидка

**Набор новых участников по старой студенческой скидке прекращён 25 июня 2026 года** (причина — мошенничество). Кто уже активировал, сохраняет тариф до истечения плана, дальше Pro продолжается по обычным $20/мес. Замена: бакалавры смогут получать кредиты и скидки на кампусных и онлайн-мероприятиях «начиная с этой осени»; магистранты, аспиранты, академические исследователи и преподаватели могут запросить кредиты через форму. Процент или сумма старой скидки на текущей странице не указаны.

## 16. Как не выйти за лимит: практические советы

1. **Проверьте, в каком режиме у вас Auto.** Balance и Intelligence стоят в 2–4 раза дороже Cost. Это самая частая причина неожиданного роста счёта.
2. **Пользуйтесь моделями Cursor для рутины.** Composer 2.5 ($0,5 вход / $2,5 выход) расходует отдельный пул, которого «значительно больше», и не облагается Cursor Token Rate. Grok 4.5 в 3 раза «дороже» Composer по расходу пула.
3. **Осторожнее с fast-режимами.** Composer 2.5 fast стоит $3/$15 против $0,5/$2,5 у обычного — в 6 раз дороже. Fast у GPT-5.6 и GPT-5.4 — ×2. Claude Opus 4.7 fast — $30/$150, это самая дорогая позиция в прайсе.
4. **Задайте spend limit сразу**, а не после первого счёта: [cursor.com/dashboard/spending](https://cursor.com/dashboard/spending). И добавьте spend alert на комфортный порог.
5. **Следите за длиной контекста.** Токены входа считаются на каждом шаге агента, поэтому долгие сессии с огромным контекстом дороги. Для облачных агентов размер контекста выбирается явно и прямо влияет на счёт.
6. **Используйте кэш в свою пользу.** Продолжение той же беседы дешевле, чем начало новой с тем же контекстом: чтение кэша обычно составляет 10 % цены входа.
7. **Не запускайте Bugbot на всё подряд** — в среднем $1,00–1,50 за прогон, а уровень High дороже.
8. **Считайте экономику тарифа.** Если стабильно доплачиваете более $40 в месяц сверх Pro, дешевле Pro+ ($60 при включённых $70). Если более $200 сверх — считайте Ultra ($200 при включённых $400).
9. **Claude Sonnet 5 до 31 августа 2026** идёт по акции $2/$10 вместо $3/$15 — временно это одна из самых выгодных сильных моделей.
10. **Помните про даты сброса.** Лимит сбрасывается по дате подписки, остаток не переносится — в конце цикла остатком имеет смысл пользоваться, а не экономить его.

## 17. Про «rate limits» и что изменилось с 2025 года

Об этом стоит сказать отдельно, потому что в интернете очень много устаревших статей.

Схема с **«burst rate limit» и «local rate limit»** (короткие всплески активности с медленным восстановлением и лимит, полностью восстанавливающийся раз в несколько часов) **отсутствует в текущей официальной документации Cursor**. Страница `cursor.com/docs/account/pricing/rate-limits` отдаёт 404. Эта модель относилась к периоду 2025 года с «безлимитом с ограничением частоты» и сегодня встречается только в сторонних блогах. Считайте её **неактуальной**.

Что вместо неё сейчас: **месячные пулы использования** (Cursor Models + Other Models), сбрасывающиеся вместе с биллинговым циклом, плюс **лимиты траты**. Никакого документированного механизма почасового или поминутного восстановления лимитов для пользовательских запросов к моделям нет.

Понятия **«fast requests» и «slow requests»** в текущей документации тоже отсутствуют. Сегодня «fast» — это лишь отдельные варианты моделей со своими ценами (Grok 4.5 Fast, Composer 2.5 fast, GPT-5 Fast, fast-режимы GPT-5.4/5.5/5.6, Claude Opus 4.7/4.8/5 fast). Старое понятие «fast requests» упоминается только на странице возвратов.

Численные лимиты частоты запросов опубликованы **только для API Bugbot** (30 и 60 запросов в минуту на команду, см. раздел 11). Для моделей есть лишь два относительных утверждения: у GPT-5.1 Codex Mini лимиты в 4 раза выше, чем у GPT-5.1 Codex, а у Gemini 3 Pro Image Preview лимиты строже.

## 18. Чего нет в официальной документации

Чтобы вы не искали зря и не верили случайным цифрам из интернета — вот что официально **не документировано**:

1. **Burst и local rate limits**, периоды их восстановления и числовые лимиты частоты запросов для пользователей по моделям.
2. Точный текст сообщения «вы достигли лимита» и набор предлагаемых в нём вариантов.
3. **Точный размер пула Cursor Models** на любом тарифе — только «щедрый», «значительно больше» и для Start «Grok расходует примерно в 3 раза быстрее Composer».
4. **Точная сумма включённой квоты Teams Standard** — только «×5» для Premium относительно неё.
5. **Точные числа для Hobby** (запросы, токены, Tab-автодополнения).
6. **Годовые цены в долларах** для любого тарифа — только «экономия 20 %» для Teams.
7. **Актуальный прайс Bugbot за ревью** — только средние $1,00–1,50 за прогон.
8. **Максимальный размер файла** для контекста или чтения агентом.
9. **Числовой предел параллельных облачных агентов** и отдельная плата за машинное время облачного агента сверх токенов.
10. **Минимальное число мест** для Teams, кроме требования «хотя бы один админ и один платный участник».
11. **Предупреждение в процентах** от включённого лимита — есть только пороговые оповещения по on-demand.
12. **Цена места Enterprise** — только «Custom / свяжитесь с отделом продаж».
13. **Процент старой студенческой скидки** на текущей странице (программа закрыта для новых участников с 25 июня 2026).
