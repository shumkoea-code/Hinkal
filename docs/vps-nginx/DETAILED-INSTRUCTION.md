## 0. Как читать названия в подписке (важно)

После **обновления подписки** профили подписаны так, чтобы было видно, **на каком устройстве их брать**:

| Префикс в имени | Значит |
| --- | --- |
| **ТЕЛ+ПК** | Подходит и для **телефона**, и для **компьютера** |
| **ПК·WiFi** | Лучше для **ПК / домашнего Wi‑Fi**. На мобильном LTE Reality часто режут |
| **ЗАПАС** | Резервные порты не 443 (админ/тест) |
| **★** | Рекомендуемый выбор для телефона |

### Актуальный список в клиенте

| Имя | Устройства | Тип | Когда включать |
| --- | --- | --- | --- |
| **ТЕЛ+ПК · TLS-WS ★** | Телефон + ПК | WS + TLS | **Телефон / LTE — первый выбор** |
| **ТЕЛ+ПК · gRPC** (`security=tls`) | Телефон + ПК | gRPC + TLS | Запас на телефоне |
| **ТЕЛ+ПК · gRPC** (`security=none`) | Телефон + ПК | gRPC без TLS | Старый вариант, который раньше работал |
| **ПК·WiFi · Stealth Reality** | ПК / Wi‑Fi | Reality + XHTTP | Основной скрытный на ПК |
| **ПК·WiFi · Speed Vision** | ПК / Wi‑Fi | Reality + TCP Vision | Если нужен быстрее |
| **ПК·WiFi · Alt Samsung** | ПК / Wi‑Fi | Reality + XHTTP | Если CF/Apple SNI режут |

Замечания по отображению:

1. У **первого** профиля может быть хвост `-логин` (например `…★-shumkoea`) — это метка аккаунта 3X-UI, не ошибка.
2. Два профиля **gRPC** называются одинаково — различайте по полю **security**: `tls` или `none` в карточке / URI.
3. Текст объявления подписки (`subAnnounce`) в клиентах, которые его показывают, повторяет ту же подсказку.

**Без обновления подписки старые имена не появятся.**

## 1. Одной фразой: что сейчас работает

На **одном порту 443** одновременно живут:

1. Сайт портала — https://tyoung.idivles.ru/
2. Маскировочная страница — https://v1.idivles.ru/
3. Несколько вариантов VPN (VLESS) — тоже на `v1.idivles.ru:443`

Снаружи это выглядит как обычный HTTPS-сервер. Разные виды трафика nginx разделяет по **SNI** (имя сервера в начале TLS-рукопожатия) или по тому, что TLS вообще нет.

## 2. Простыми словами: как это устроено

### 2.1. Почему нельзя было «просто открыть порт 10443»

Xray слушает VPN **только на localhost**:

| Внутренний порт | Профиль |
| --- | --- |
| `127.0.0.1:10443` | gRPC |
| `127.0.0.1:10444` | Stealth Reality + XHTTP |
| `127.0.0.1:10445` | Speed Reality + TCP Vision |
| `127.0.0.1:10446` | Alt Reality + XHTTP (Samsung) |
| `127.0.0.1:10447` | Mobile TLS + WebSocket |

Эти порты **нельзя** прописывать в клиенте. С интернета до них не достучаться (и так задумано: безопаснее).

Публичная дверь одна: **порт 443**.  
nginx смотрит, «к кому клиент пришёл», и пересылает на нужный внутренний порт.

### 2.2. Карта порта 443 (SNI-мультиплексор)

```text
                    Интернет → :443 (nginx stream, ssl_preread)
                                      │
          ┌───────────┬───────────────┼───────────────┬──────────────┬────────────┐
          │           │               │               │              │            │
   SNI=tyoung   SNI=v1.idivles   SNI=cloudflare  SNI=apple    SNI=samsung   нет TLS /
   .idivles.ru       .ru              / cf            / icloud                     default
          │           │               │               │              │            │
          ▼           ▼               ▼               ▼              ▼            ▼
       :8443       :8445           :10444          :10445         :10446       :10443
       сайт        маска +         STEALTH         SPEED          ALT          gRPC
       портала     пути VPN        Reality         Reality        Reality      (legacy)
                   /gun, /ws…      XHTTP           TCP+Vision     XHTTP
```

| Если клиент говорит в TLS: «я иду на …» | Куда попадёт |
| --- | --- |
| `tyoung.idivles.ru` | Сайт портала |
| `v1.idivles.ru` | Маска + мобильный VPN (WS/gRPC по путям) |
| `www.cloudflare.com` | Stealth Reality |
| `www.apple.com` (и iCloud) | Speed Reality |
| `www.samsung.com` | Alt Reality |
| TLS нет / SNI не из списка | Legacy gRPC |

Именно поэтому:

- в браузере открывается сайт по своему имени;
- VPN-клиент Reality подставляет **чужой** SNI (Cloudflare/Apple/Samsung), но стучится на IP нашего сервера;
- старый gRPC без TLS попадает в `default`.

### 2.3. Два разных способа «спрятать» VPN

| Способ | Как выглядит снаружи | Где лучше |
| --- | --- | --- |
| **Настоящий TLS на свой домен** (`v1.idivles.ru`) | Обычный HTTPS к нашему сайту | **Телефон / мобильный интернет** |
| **REALITY** (поддельный SNI чужого сайта) | Похоже на HTTPS к Cloudflare/Apple/Samsung | ПК, домашний Wi‑Fi; на LTE часто режут |

## 3. Почему на телефоне работал только gRPC

### Что происходило

1. В подписке были Reality-профили (Stealth / Speed / Alt) и старый gRPC.
2. На **мобильном интернете** операторский DPI часто ломает Reality: в ClientHello написано «иду на cloudflare.com», а IP — не Cloudflare.
3. gRPC с `security=none` **не делает** такой поддельный TLS — пакеты идут иначе и чаще проходят.
4. Отсюда ощущение: «на телефоне живёт только grpc, остальные три — нет».

### Что сделали

Добавлены профили, которые снаружи = **обычный заход на `https://v1.idivles.ru`**:

1. **ТЕЛ+ПК · TLS-WS ★** — WebSocket внутри настоящего TLS  
2. **ТЕЛ+ПК · gRPC** (`tls`) — gRPC через путь `/gun` после настоящего TLS  

Их нужно ставить **первыми на телефоне**. Reality оставить для Wi‑Fi/ПК или как запас.

## 4. Все профили в подписке (что выбирать)

См. таблицу в **§0** — это главный ориентир по именам.

После обновления подписки обычно **6 линков** на `v1.idivles.ru:443`.

### Как отличить правильный линк глазами

**Телефон (рекомендуется) — имя `ТЕЛ+ПК · TLS-WS ★`:**
```text
vless://…@v1.idivles.ru:443?type=ws&security=tls&path=/c410aeaf855fdf46bb88…
```

**Телефон (запас) — `ТЕЛ+ПК · gRPC` + `security=tls`:**
```text
vless://…@v1.idivles.ru:443?type=grpc&security=tls&serviceName=gun…
```

**Старый gRPC — тот же заголовок, но `security=none`:**
```text
vless://…@v1.idivles.ru:443?type=grpc&security=none&serviceName=gun…
```

**ПК Stealth — имя `ПК·WiFi · Stealth Reality`:**
```text
vless://…@v1.idivles.ru:443?type=xhttp&security=reality&sni=www.cloudflare.com&fp=chrome&pbk=…&sid=…
```

### Чего в клиенте быть не должно

| Плохо | Почему |
| --- | --- |
| Адрес `localhost` / `127.0.0.1` | Это внутренний адрес сервера; на телефоне бессмысленно |
| Порт `10443`, `10444`, `10445`, `10446`, `10447` | Внутренние backend’ы, снаружи закрыты |
| Пустой `pbk` у Reality | Битый/устаревший профиль |

Рабочий публичный адрес почти всегда: **`v1.idivles.ru` порт `443`**.

| Clash | `https://v1.idivles.ru:2096/clash/<subId>` |

### Где взять `subId` в панели

1. Открыть панель: https://v1.idivles.ru:444/t0HAtL75Ph0mDWoZPq/
2. Войти под админом (или найти своего клиента).
3. Клиенты / Inbounds → нужный пользователь.
4. Скопировать **Subscription URL** / `subId` (кнопка подписки / QR).

Пример (только как образец формата, не общий ключ):  
у пользователя `shumkoea` subId выглядит как `7c4kwxfrltl94c7v` →  
`https://v1.idivles.ru:2096/sub/pepewtfa/7c4kwxfrltl94c7v`

Каждому клиенту — **свой** `subId`.

## 6. Пошагово: телефон (Android / iOS)

### 6.1. Приложение

Подойдёт одно из:

- **Hiddify**
- **Happ**
- **v2rayNG** (Android)
- **Streisand** / **Shadowrocket** (iOS; где доступно)
- любой клиент на **Xray-core ≥ 26.3.27**

Старые сборки часто не понимают `xhttp` и новые Reality — для телефона это не критично, если берёте **ТЕЛ+ПК · TLS-WS ★**, но обновлять клиент всё равно стоит.

### 6.2. Импорт

1. Удалите **старую** подписку этого сервера (чтобы не остались битые `localhost` / старые Reality-only наборы).
2. Добавьте подписку URL из раздела 5.
3. Дождитесь обновления списка серверов.
4. В списке найдите **ТЕЛ+ПК · TLS-WS ★** (обычно первый; может быть с хвостом `-вашлогин`).
5. Подключитесь только к нему.
6. Проверьте IP (любой «what is my ip»): должен быть `77.110.125.241` (или актуальный IP VPS).

### 6.3. Если TLS-WS ★ не коннектится

По порядку:

1. Возьмите **ТЕЛ+ПК · gRPC** с **`security=tls`** (не `none`).
2. Затем тот же **ТЕЛ+ПК · gRPC** с `security=none` (тот, что раньше работал).
3. Проверьте, что в URI адрес `v1.idivles.ru:443`, не `localhost`.
4. Отключите «чужой» DNS/фильтры в клиенте на тест.
5. Попробуйте с Wi‑Fi и с LTE отдельно — так видно, режет ли оператор.

Reality (Stealth/Speed/Alt) на LTE можете не мучить: часто это бесполезно из‑за DPI.

### 6.4. Типичные ошибки на телефоне

| Симптом | Что проверить |
| --- | --- |
| Крутится и отваливается | Выбран `ПК·WiFi · Reality` вместо **ТЕЛ+ПК · TLS-WS ★** |
| «Connection reset» | Старая подписка / порт 1044x |
| Сайт tyoung открывается, VPN нет | Нормально для сайтов; VPN — отдельным профилем из sub |
| Работает только домашний Wi‑Fi | На LTE нужен **ТЕЛ+ПК · TLS-WS ★**; Reality там режут |

## 7. Пошагово: компьютер

1. Клиент: **v2rayN**, **Hiddify**, **Nekoray** и т.п. (свежий Xray).
2. Импорт той же подписки.
3. Предпочтительно:
   - **ПК·WiFi · Stealth Reality** — основной скрытный;
   - **ПК·WiFi · Speed Vision** — если Stealth тормозит;
   - **ПК·WiFi · Alt Samsung** — если CF/Apple SNI режут;
   - **ТЕЛ+ПК · TLS-WS ★** — тоже можно, он универсальный.
4. Не указывайте вручную порты `10443+`.

## 8. Сайты (они не «ломают» VPN)

| URL | Что это |
| --- | --- |
| https://tyoung.idivles.ru/ | Боевой портал (Next.js / sochi-portal) |
| https://v1.idivles.ru/ | Маскировочная страница; плюс пути для мобильного VPN |

Оба ходят на **тот же 443**, что и VPN. Браузер шлёт SNI своего домена → попадает на сайт.  
VPN-клиент шлёт другой SNI или идёт на пути `/gun` и WS-path → попадает в Xray.

Если сайт открывается, а VPN нет — проблема почти всегда в **выбранном профиле клиента**, а не в «упавшем nginx».

## 11. Разбор: «почему раньше ломался v1 в браузере»

До настройки маски:

- SNI `v1.idivles.ru` не был прописан в stream-карте;
- запрос падал в Xray (gRPC) → браузер получал «не HTTPS» → `wrong version number` / ERR_SSL.

Сейчас:

- SNI `v1.idivles.ru` → `127.0.0.1:8445` (nginx + сертификат v1);
- браузер видит сайт;
- VPN с TLS на v1 ходит в `location` с путями WS и `/gun`.

```bash
# сайты

# подписка (подставьте свой subId)
```

В выводе `base64 -d` должны быть строки `vless://…@v1.idivles.ru:443…`, среди них:

- имя с **ТЕЛ+ПК · TLS-WS ★** и `type=ws` + `security=tls`;

Не должно быть `@localhost` и портов `1044x` в пользовательских линках.

## 13. FAQ

**Q: Можно ли оставить только один профиль?**  
A: На телефоне достаточно **ТЕЛ+ПК · TLS-WS ★** (+ запас gRPC). Reality имеет смысл держать для ПК и на случай смены сети.

**Q: Нужно ли обновлять подписку после каждой правки сервера?**  
A: Да, если менялись hosts/inbounds. Иначе в клиенте останутся старые URI.

**Q: Безопасно ли светить панель на 444?**  
A: Панель уже за длинным `webBasePath`. Всё равно не публикуйте пароль и не шарьте subId посторонним: subId = доступ к конфигам клиента.

**Q: Почему в Mobile-линке иногда пустой `sni=`?**  
A: Панель так отдаёт при `externalProxy`. Большинство клиентов подставляют SNI = адрес хоста (`v1.idivles.ru`) — для нашего сертификата это правильно. Мы это проверяли live.

**Q: Когда отключать старый gRPC none?**  
A: Когда все обновили подписку и стабильно сидят на TLS-WS или Reality. Пока — оставляем для совместимости.

**Q: XHTTP / Reality не находятся в старом приложении**  
A: Обновите клиент. На телефоне пользуйтесь **ТЕЛ+ПК · TLS-WS ★** — ему XHTTP не нужен.

## 14.1. Роутер Keenetic (кратко)

Штатный Keenetic **не открывает** VLESS из подписки. Нужен:

1. **WireGuard** — конфиг на сервере `/root/keenetic-wg/keenetic-client.conf` (проверено handshake на `:51820`), или  
2. **XKeen (Entware)** — тогда из подписки берите **ТЕЛ+ПК · TLS-WS ★** или **ПК·WiFi · Speed Vision**.

Подробно: [KEENETIC-ROUTER.md](./KEENETIC-ROUTER.md).
